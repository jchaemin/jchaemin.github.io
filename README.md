# Chaemin Jang — personal site

Static site for GitHub Pages, generated by `python3 build.py` (standard library only).

## Adding a paper
Add one entry to `content/publications.json` and run `python3 build.py`. That's all:
it appears in the right year, newest first, with arXiv/PDF links if the URL is on arXiv.

```json
{ "title": "...", "url": "https://arxiv.org/abs/2701.01234",
  "authors": ["Chaemin Jang", "..."], "venue": "ACL 2027",
  "note": "optional, e.g. Oral", "year": 2027, "research_area": "internals",
  "links": [{ "label": "Project", "url": "papers/slug/" }, { "label": "Code", "url": "https://github.com/..." }] }
```
`research_area` is `internals` or `simulation`; it places the paper under that topic and filter.
`year` is only needed when neither the venue nor the arXiv id contains it.
Optional: `"venue_short": "ACL"` overrides the tag text.

## Optional extras (`content/research.json`, keyed by arXiv id)
- `line`: a one-sentence TL;DR, shown when the visitor expands "+ TL;DR".

## Research topics
The two topics, their one-line descriptions and the two pixel scenes (the model seen
from inside, and the model playing people) are defined in `TOPICS`, `scene_internals()`
and `scene_simulation()` in `build.py`.

## Profile links (top bar)
Edit `profiles` in `content/site.json`. Each entry is `{ "label": "...", "url": "..." }`, shown in
order; an empty `url` hides it. X and LinkedIn are already there, blank:
```json
{ "label": "X", "url": "https://x.com/wkdcoals" },
{ "label": "LinkedIn", "url": "https://www.linkedin.com/in/chaemin-jang-091365257/" }
```

## Research page (`/research/`)
Built from `content/topics.json` (overview, and per topic: intro and questions) and each
paper's `summary` in `research.json`. Papers appear under their `research_area` automatically.

## Now, news and projects
- `content/now.json`: the NOW box on the homepage (`updated` + 3–5 short `items`).
- `content/news.json`: newest first. Each item has `date` (`YYYY-MM`), `kind`
  (`accepted`, `preprint`, `talk` or `visit`), a bold `head`, an optional `title` and `url`.
  Items dated after the build month get a SOON badge automatically, so rebuild once the event has passed.
  On screens 1200px and wider the news list sits in a sticky side column; below that it is a scroll box under NOW.
- `content/projects.json`: funded projects. Each gets a page at `projects/<slug>/` with `summary`,
  `sections` (heading + paras/bullets), optional `image`, `links`, `team`, `role` and related `papers` (arXiv ids).
  `topic` ties a project to a research topic; topics with projects show a "Show its N projects" button.

## Other content
- `content/site.json`: name, links, intro text
- `content/experience.json`: roles. Each one becomes a save slot and a block on the timeline (`track` picks the lane: `research` or `industry`; `end_year: null` marks the current role). A new organization can get its own 10×10 icon in `EXP_ICONS` in `build.py`; otherwise it shows the robot.
- `content/project-page.html`: the COLM project page

## Design
Pixel edition. Documented at the top of `assets/css/style.css`. Sprites are hand-drawn
16x16 grids in `build.py` (ME_SPRITE, BOT_BASE, BOT_FACES). The title-screen dialogue uses
`say`/`but` from research.json. Earlier versions are git tags (v8-prose, v10-knows-does, v11-sentence).
Instrument Serif carries the voice
(the cycling sentence and each finding); Inter carries facts. Fonts are self-hosted in
`assets/fonts/` (SIL Open Font License).
